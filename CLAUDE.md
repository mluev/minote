# Minote

A quiet place to write: plain Markdown files, a library sidebar, everything else in the menus. The library is real folders on disk, nested as deep as wanted: the sidebar shows them as a tree (folders open and close, a note count, "+" on hover makes a note there), notes and folders drag into a folder or to a place among their siblings, and a folder can keep an order of one's own (Manual, kept in a hidden `.minote-folder` inside it, so it travels and syncs with the folder). Rows are one line, folders and notes alike, icons in one column. Under the sidebar's header: "Notes" (or a path back from a folder looked into with "Show Only This Folder"), the view options (our own panel: Group by Folder / Date / None, Sort by Manual / Last Updated / Date Created / Title + direction, Show Dates / Note Counts / Locked) and New Folder (⇧⌘N). Search is a launcher-style palette (⌘J or ⇧⌘F, or the magnifying glass in the sidebar's header): notes by title and text, folders and commands, keyboard first. The sidebar is driven by the keyboard too: ↑↓ through every row (a note opens, a folder takes the cursor), ←→ close / open folders and step out / in, Return toggles a folder or goes to the page, ⌫ trashes. Nothing in the window is the system's: menus, panels, inputs and the palette are drawn by Minote (`Chrome/`), only the menu bar and sheets are AppKit's. Sorts belong to folders and are inherited downwards; the menu sets the sort of the folder at the top of the list. Group by, Show and closed folders are per device (`SidebarPreferences`). iOS shows the same tree and menus, without dragging. Any Markdown file on the Mac (Finder, File ▸ Open… ⌘O, Open Recent, the Dock) opens as a tab of the front window (or a window of its own when none is open) and is edited in place. Tabs on the Mac are Minote's own, IDE-style: a solid bar at the very top of the window (the window buttons sit in it), tabs as wide as fit up to a maximum, scrolling past a minimum; each tab is a rounded plate shaped and shaded like a sidebar row (`SidebarMetrics.rowCornerRadius`). With a single tab the bar shows no tab: it takes the page's paper, keeping its height and buttons, so a second tab doesn't move the page. A note opened takes the place of a library tab nobody typed in (its title is italic; a double-click or "Keep Open" keeps it), otherwise it gets a new tab; files from Finder always get their own tab. ⌘T new tab, ⌘W close it (middle-click too), ⇧⌘W close the window, ⌘1…⌘9, ⌘⇧] / ⌘⇧[, ⌃Tab; tabs drag along the bar, out into a window of their own and into another window's bar; library tabs come back at the next launch. The editor renders Markdown: no markup symbols show. Block markup is hidden or drawn as what it means (bullets •◦▪, clickable task boxes, quote bars, rules, code boxes, table lines); only the *inline* formatting under the caret (`**`, `[]()`) reveals its symbols, so it can be edited. View ▸ Preview (⌘R) is read-only: nothing reveals, a click follows links. In Preview (Mac) a rail of dashes on the page's right edge, one per heading, morphs on hover into a card of heading titles; a click glides the page to that heading and puts the hidden caret there, so leaving Preview continues at it. While editing, ⌘-click follows a link (iOS: tap it when not typing) and hovering shows its address. View ▸ Show Markdown Syntax switches to iA-style dimmed markup. The "Aa" button at the end of the tab bar (Mac) opens a panel with text size, theme (System / Light / Sepia / Dark) and font: the same preferences as the View menu, for writing and Preview alike. Locked notes: any note (File ▸ Lock Note), or the whole library (Settings ▸ Lock: Whole Library), is encrypted on disk as `Title.mdlock`, so other apps and tools reading the folder see ciphertext; titles (file names) stay readable by design. One password for the library (at least 12 characters), typed or Touch ID / Face ID, plus a recovery key (24 characters, shown once to print or keep, never stored) for when it's forgotten: "Forgot Password?" sets a new one with Touch ID or the recovery key; one unlock opens every locked note until they lock again (screen lock, sleep, idle time from Settings, leaving the app on iOS, quit, Lock Now ⌃⌘L). Philosophy and interaction model follow iA Writer; name, icon and typeface are our own (iA's fonts may not be bundled — we use IBM Plex Mono, OFL).

## Commands

```bash
scripts/test.sh                      # unit tests (Swift Testing); CI (.github/workflows/ci.yml) runs them and builds both apps on every PR
scripts/build-app.sh --run           # Mac app → build/Minote.app (sandboxed, ad-hoc signed), relaunch
scripts/build-app.sh --universal     # arm64 + x86_64
scripts/build-ios-preview.sh --run   # iOS app compiled for Mac Catalyst → build/Minote iOS Preview.app
xcodegen generate && xcodebuild test -project Minote.xcodeproj -scheme Minote-iOS -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO   # iOS UI tests (real taps)
swift scripts/make-icon.swift        # regenerate AppIcon.icns + Assets.xcassets
xcodegen generate                    # Minote.xcodeproj for App Store archives (needs Xcode to build)
```

## Layout

- `Sources/MinoteKit` — Foundation only, shared by every platform, fully unit-tested.
  - `Library` (`@MainActor @Observable`): notes, selection, drafts, debounced autosave, auto-naming, trash/undo, reconciling outside changes. All disk work for a note is serialized through `enqueue`; a folder command holds every note it touches with `enqueue(holding:)` (their pending edits written first) and queues behind the other folder commands (`organiseQueueID`). A note's persistent identity is its path in the library (`Note.relativePath`, "Work/Ideas.md"; `note(atPath:)`): saved tabs, the last selection and relocation use it, and a bare name saved by an earlier build reads as a note at the top. `folders`, `folderSettings`; `organisationHandler` tells the app about folders renamed, moved or trashed and notes moved. Over a single-file store (`isSingleFile`) it holds just that note: no drafts, no saved selection, and a file deleted elsewhere keeps its window (edits are written back to the same path). It serves several editors at once (one per Mac tab): `show(_:in:)`, `activate(_:)`, `detach(_:)`; `selectedID` is the front editor's note, and setting it shows the note in the front editor (iOS has one editor, where nothing changed). Opening on the user's behalf goes through `open(_:)` → `openHandler`; a removed note's editor asks `shownNoteRemovedHandler`.
  - `Folders/`: `FolderPath` (a folder relative to the library folder; `rebasing` for renames and moves), `FolderSettings` (the `.minote-folder` codec: version, sort, reversed, order of "Name/" folders and note stems; unknown versions are `.unreadable` and never rewritten automatically) and `FolderOrdering` (a folder's children in order, inherited sorts; what the sidebar shows and what reordering stores both ask it), `Library+Folders` (new/rename/move/trash/restore folders, `moveNote`, `place`, `setSort`, with undo), `SidebarRows` (pure: rows for every Group by × sort × filter × folder looked into, date sections; `SidebarDrop.resolve` decides where a drag lands, from row frames), `SidebarPreferences` (view + closed folders, per device), `FolderWatcher` (one `PathWatcher` per folder, for iOS).
  - `Tabs`: `OpenPlacement` (where an opened note goes: focus its tab, replace the front one, new tab, new window), `SavedTabs` (library tabs per window, by file name, with the untouched ones, under `OpenTabs`) and `TabStripLayout` (tab widths, scrolling, where a dragged tab lands).
  - `NoteFileStore` (actor): scan (`scanTree`: every folder below the library folder, skipping hidden items, packages and links; each folder's settings), safe write (`replaceItemAt` + xattr copy), create, rename, trash, folder commands (`createFolder`, `renameFolder`, `moveFolder`, `moveNote`, `trashFolder`, `restoreFolder`, `writeFolderSettings`; renames and moves never replace: `renamex_np` with `RENAME_EXCL`). Names are unique per folder. `init(file:)` is single-file mode for a file opened from elsewhere: only that file, always coordinated, no naming tag, written in place when the sandbox refuses a replace (the grant covers the file, not its folder); create/rename/duplicate/trash throw. In iCloud (`isUbiquitous`): coordinated I/O, downloads `.icloud` placeholders, saves conflict versions as "(conflict)" notes. Emptying a non-empty note first copies it to `LibraryLocation.backupDirectory()` (Application Support/Minote/Backups, device-local, newest 50).
  - `LibraryStorageSwitcher`: opens the library locally or in iCloud Drive and moves notes between them (`LibraryLocation.moveNotes`: `setUbiquitous`, downloads placeholders first, keeps going past failures and reports what stayed). Notes written locally while iCloud was unavailable join iCloud at the next launch.
  - `Markdown/`: `MarkdownLexer` (per-line CommonMark/GFM styling spans, list markers, quote depth, links), `FenceIndex` (incremental code-fence tracking), `MarkdownEditing` (Format actions as pure `TextEdit`s; `hiddenMarkup`/`adjustedCaret`/`deleteMarkup` for the rendered view), `MarkdownLinks` (resolves references, footnotes, `#heading` anchors, other notes), `MarkdownOutline` (the headings the page renders, outside code blocks; `section(at:)`), `TextStatistics`, `Lines` (`NSString.forEachLine`, `characters(in:)`, `NSRange.clamped(to:)`). Anything that reads a line's markers asks `MarkdownLexer` (e.g. `LinePrefix` for Return/Tab/list toggles), so what's drawn and what's edited never disagree.
  - `PathWatcher`: vnode watch of a file or folder that follows replace-on-save (an opened file on the Mac, the library folder on iOS).
  - `Vault/`: locked notes. `LockedNoteFile` (format: `MINOTE-LOCKED\n`, version, header = the password's `KeyRecord`, AES-GCM box with everything before it as AAD), `LibraryKey` (random 256-bit key per password, wrapped by PBKDF2-HMAC-SHA256 from CommonCrypto, 600k rounds stored per record), `NoteSealer` (current key + earlier ones for reading), `VaultRecord` (`.minote-vault` in the library folder: password record + `LockScope` with `scopeRevision`, signed with the library key in `scopeCheck`; mirrored in UserDefaults `LockVault` for when the folder's isn't readable), `RecoveryCode` (24 symbols, no I/O/0/1; `KeyRecord.recovery` holds the key sealed with it, like the password's) and `PasswordPolicy` (12 characters, a hint that doesn't contain the password, the hint shown after 3 wrong attempts), `BiometricUnlock` (`SecureEnclaveUnlock`: the key sealed by ECIES to a Secure Enclave key gated by `.biometryCurrentSet`, stored in Application Support/Minote/Unlock; no keychain, so ad-hoc builds work; `FakeBiometricUnlock` for tests/driver/UI tests), `LockController` (what the UI talks to: unlock, Touch ID, idle timer, `LockTimeout`, per-device preferences). In `Library`: `setPassword`, `unlock(password:)` / `unlock(with:)`, `lockNow`, `lock(_:)` / `removeLock(_:)` (`NoteFileStore.convert`), `changePassword(from:)` / `changePassword(with:)` (the old key from the password, Touch ID or `key(recoveryCode:)`; new key and new recovery key, every note resealed), `makeRecoveryCode` (same key, new recovery key, notes resealed), `setScope`, `removePassword`.
- `Sources/MinoteEditor` — AppKit/UIKit shared look: `EditorTheme` (caret, parts of speech, metrics), `EditorPalette` (the page's colors, one instance per `EditorPaper`: standard or sepia), `EditorStyleSheet` (fonts + palette + geometry), `MarkdownStyler` (rendered/source views; hidden markup = 0.01 pt clear font; drawn markup = clear glyphs + `.minoteMark`/`.minoteBlock` attributes), `MarkdownLayoutFragment` (TextKit 2 fragment that draws those marks; installed by `EditorTextEngine.attach(to:)`), `EditorTextEngine` (text-storage delegate: incremental restyle, caret reveal, Preview, Focus mode, caret snapping out of hidden markup, fence-aware Return/Tab/Backspace edits, link/task-box hit testing, title-line and title-prefix queries, `outline()`), `FormatAction`, `SharedViews` (SwiftUI shared by both apps: `ViewState`, `EditorPreferences` — the View menu's `@AppStorage` settings, `FormatMenuItems`, `libraryErrorAlert`). The outline beside the page, shared for iOS later: `OutlineLayout` (rail and card geometry, also used for hit testing), `OutlineMotion` (one `progress`, 0 rail → 1 card, places every element; pure and tested), `OutlineScrolling` (reading line, landing place), `OutlineRailView` (SwiftUI, only draws). Branch on `#if os(macOS)`, never `canImport(AppKit)` (true on Catalyst).
- `Sources/Minote` — macOS app (SwiftUI shell + TextKit 2 `NSTextView`). `Window/Workspace` (owned by `AppDelegate`): every window and tab, the shared library (loaded on first need), where opened notes and files go, moving tabs between windows, recents, saving/termination, tabs kept across launches. `Window/PageWindow`: one AppKit window (not restorable, no system tabs) holding `WindowState` (its tabs, the one in front, the sidebar) and `PageView` = `SidebarColumn` + (`TabBar` over `EditorPage`). `Window/PageTab`: one tab, with its own `EditorCoordinator`, showing a library note or an `OpenedFile` (`Files/`: a single-file `Library` watched by a `PathWatcher`); switching tabs swaps the page's scroll view. `Window/TabBar` (tabs, dragging, "+", the sidebar toggle, `ChromeButtonStyle`), `Window/TitlebarLayout` (the window buttons centered in the bar, `WindowButtonsKeeper`, `WindowDragArea` for the bar's empty parts). `Sidebar/SidebarColumn`: header (window buttons, toggle, New Note), search field, the library bar (path back, view menu, New Folder), notes (`SidebarView`: rows from `SidebarRows`, `FolderRow` with rename in place, `NoteRow`, our own drag with `SidebarGeometry` holding row frames outside SwiftUI state, the `TabDragPreview` chip, edge auto-scroll, opening a closed folder held over), resizable edge. `EditorPage` is the page of the tab in front; "Aa" is `Editor/TextSettingsPanel`. `Chrome/`: `ChromeOverlay` (one overlay per window, `WindowState.overlay`: a menu at a point, the view options or "Aa" panel under its button, the search palette; `ChromeOverlayLayer` over `PageView`, `Placed` keeps panels inside the window, `ChromeMotion` springs that fall back to fades with Reduce Motion, `chromeSurface`), `ChromeMenu` (our menus: checkmarks, details, indented rows, submenus to the side, ↑↓→←↩⎋). `Sidebar/ViewOptionsPanel`, `Search/SearchPalette` (+ `PaletteCommand`; matching is `MinoteKit/Search/LibrarySearch`: `Fuzzy`, note hits with snippets). `PageTheme` (View ▸ Appearance) picks the app appearance and the paper; Sepia is a light appearance on sepia paper. `Security/`: `LockViews` (`UnlockForm`, `LockedNotePanel` shown by `EditorPage` for a sealed note, `AppLockView` over the window in Whole library mode, `PasswordSheet`), `SecuritySettingsView` (the Settings scene's only content), `AutoLock` (sleep, screen lock, screen saver, user switch). `Editor/Outline/`: `OutlineController` (owned by `EditorCoordinator`: headings, current section, hover → card, going to a heading), `OutlineOverlayView` (AppKit container in `EditorScrollView` that owns every event, with a passive SwiftUI host inside), `ScrollGlide` (display-link glide to a heading). `Debug/DebugDriver.swift` (DEBUG only): with `MINOTE_DRIVER=1` the app takes commands (click/key/type/hover/snapshot/outline/tabs/open/openfile/mouse/droptab/chrome…) from `$TMPDIR/minote-driver/in`, against its own `DriverNotes` library — interaction tests without the screen.
- `Apps/iOS` — iPhone/iPad app (SwiftUI + TextKit 2 `UITextView`). `MobileLockViews`: locked note overlay, lock screen, privacy cover, password sheet, Locked Notes settings (list toolbar ▸ Locked Notes…). Not a SwiftPM target; built by Xcode or `build-ios-preview.sh`. Module name `MinoteMobile` (`Minote` is the Mac target). `Tests/MinoteiOSUITests`: XCUITests (DEBUG seed via `MINOTE_UITEST_NOTE`; `MINOTE_UITEST_LOCKED=<password>` adds a locked note).
- `Support/` — `Minote.xcconfig` (identity + version, single source of truth), Info.plists, entitlements, privacy manifest, container migration.

## Rules that bit us

- An opened file never joins the library list and is never renamed, moved or trashed. A file that is one of the library's notes opens as a library tab instead: two editors on one file overwrite each other. Likewise a note is never shown in two tabs (`Library.show` refuses; opening it again brings its tab forward).
- Opening files must stay light: every window is AppKit's own and made on demand. The SwiftUI scene is the `Settings` scene (locked notes only, built when opened; it loads the library itself) that also hosts the menus. The library is loaded (scan, FSEvents, iCloud lookup) only when a window shows it: at a launch that opened no files (`applicationDidFinishLaunching`), on reopen (Dock, Launchpad, Spotlight), from a library command, or when a Finder window's sidebar is shown. A launch from Finder costs one window, sidebar hidden.
- A note is wrapped up (blank draft dropped, renamed to its title, emptied file trashed) when no editor shows it any more, not when the selection moves: a background tab is still open.
- The editor belongs to its tab (`PageTab` makes it; the workspace attaches it to the library at once), not to SwiftUI: routing asks the library which editor shows a note before SwiftUI has laid anything out. A tab moved to another window takes its editor along.
- `PageTab.isEdited` (the untouched-tab rule) is set once per note, not per keystroke: typing never goes through SwiftUI.
- Save state as it changes, never only at quit: `NSSupportsSuddenTermination` is on, so ⌘Q with nothing unsaved ends the app without calling `applicationShouldTerminate`. Tabs are saved on every change (`Workspace.tabsDidChange`, coalesced).
- The tab bar is ours (`allowsAutomaticWindowTabbing` is off). Its Window menu items are in `AppCommands`; the tab shortcuts and middle-click are handled in `AppDelegate` (`handleTabKey`, `handleMiddleClick`) so they work regardless of focus.
- The tab bar lies where the titlebar would be. AppKit moves the window from a press on anything there that doesn't refuse it, and SwiftUI's views don't: `PageNSWindow.sendEvent` turns moving off for presses on the bar's controls; only `WindowDragArea` moves the window. AppKit lays its titlebar out again whenever it likes (a new title puts the zoom button back, silently): `WindowButtonsKeeper` re-centers the buttons after frame changes and every window update, and `PageWindow.updateTitle` lays out at once.
- `NSEvent.clickCount` raises on anything but a mouse down/up: check the event type first. An exception swallowed inside a SwiftUI gesture leaves Swift's executor state broken and the app crashes later, somewhere unrelated.
- The sidebar draws its own rows (`SidebarView`: ScrollView + `NoteRow`, `EditorTheme.sidebar*` colors). Don't go back to a system `List(.sidebar)`: its translucency and accent-colored selection can't be restyled to match the page. Nor to `NavigationSplitView` or a window toolbar: the column, its search field and the bar are ours, so nothing floats over the page or sits under the titlebar.
- Menus act on the front tab: in `AppCommands` use `front` (`Workspace.frontTab`) for editor commands, `frontWindow` for the window's state, and `frontLibraryNote` for library-only commands (disabled for a file from Finder).
- Page colors come from the style sheet's palette (`styleSheet.palette`), never a global: a theme change is an `EditorConfiguration.paper` change, which rebuilds the style sheet and restyles like a font change. SwiftUI and window backgrounds read `PageTheme.palette`; each paper has its own color instances, so SwiftUI notices the change. Printing always uses standard ink.
- Build fonts from descriptors, not names: system faces (New York) have private names that don't resolve (`NSFont(name: ".NewYork-Regular")` is nil), and the full-size fallback left gaps where markup is hidden.
- Typing never goes through SwiftUI state. The library drives the editor via the `NoteEditor` protocol.
- Smart Return, Tab and Backspace go through `EditorTextEngine` (`newlineEdit`, `listShiftEdit`, `markupDeletion`), never `MarkdownEditing` directly: only the engine knows where code blocks are.
- Idle must cost nothing: no repeating Core Animation (the caret blinks with a timer; a repeating animation keeps the render server drawing every frame). A keystroke styles its line once: `EditorTextEngine` shifts the revealed lines with the edit so the selection change that follows doesn't restyle them.
- The lexer runs on every keystroke for the edited line: keep it linear (a long pasted line once took 21 s; see `longLinesFullOfDelimitersStayFast`).
- Files Minote didn't create are never renamed (auto-naming is gated on the `com.mlutfullaev.minote.autoname` xattr).
- TextKit 2: `baselineOffset` has its standard meaning inside a fixed line height (negative = lower); a positive one shrinks the line. `NSTextLineFragment.glyphOrigin` is the baseline *before* the offset: drawn baseline = `glyphOrigin.y - baselineOffset`. `drawInsertionPoint` is ignored, hence `CaretView`.
- Overlays above the page (`EditorScrollView.outlineOverlay`) are a plain NSView that decides hit testing, the cursor and scrolling with the same layout that draws, around a SwiftUI host whose `hitTest` is nil (`sizingOptions`, `safeAreaRegions`, `sceneBridgingOptions` all empty, or every animation frame relayouts the window). The text view's `.inVisibleRect` tracking area still fires under an overlay: `WriterTextView` asks `isPointerOverOutline` before touching hover or the cursor. Never override `scrollWheel` on the scroll view or the text view (it opts them out of responsive scrolling).
- Animate a jump to a line by its distance from the top of the page, measured again every frame (`ScrollGlide`), never with `clip.animator()`: TextKit 2 replaces estimated heights while laying out, so a fixed scroll target misses and correcting it at the end jumps.
- Never give the Mac editor's NSScrollView a bottom `contentInsets`: AppKit treats that band as outside the page, so clicks there were swallowed or started a selection to the end of the note. Scroll-past-end is `WriterTextView.bottomPadding` (taller view + `textContainerOrigin` override).
- The engine restyles whole lines inside `willProcessEditing`, which widens the edited range TextKit 2 sees; it moves a caret inside that range to its end. `WriterTextView` records the expected caret in `shouldChangeText` and restores it in `didChangeText` (typing mid-line used to jump to the next line).
- The caret never rests inside hidden block markup (`EditorTextEngine.adjustedSelection`). Only keyboard moves may step back out of a line (pass `previous` for those, nil for clicks: a click sets the selection twice). NSTextLayoutManager rendering attributes don't reliably recolor NSTextView text, so Focus mode restyles storage. After replacing the whole text, call `layoutViewport()` or only the old viewport renders.
- The SwiftPM scripts work with Command Line Tools alone: SwiftUI's `@State` is a macro whose plugin ships only with Xcode → use the `ViewState` typealias (MinoteEditor). Swift Testing's macro plugin needs `-plugin-path` (see `scripts/test.sh`). Xcode 27 is now installed too (iOS simulators, UI tests, archives).
- macOS bash is 3.2: guard empty arrays under `set -u`.
- Locked notes: a sealed note is not an empty note. `Note.text` is nil while sealed (`NoteContent.sealed`); every blank check uses `isKnownBlank` and skips sealed notes, or quitting/wrap-up would empty or trash the file. Editors showing a sealed note keep the note (never `display(nil)`) but are read-only (`isSealedDisplay`), and `editorDidChange`/`captureEditorText` ignore them.
- Never write plain text into a `.mdlock` nor sealed bytes into a plain file: `NoteFileStore.write(_ payload:)` throws. A locked note that can't be sealed (no key) waits in memory (`awaitingUnlock`) rather than go to disk in the clear. Locking converts with `removeItem`, never the Trash, and deletes the file's plain backups.
- `lockNow` is synchronous: edits not yet on disk are sealed in memory (`SealedText`) and written later without the key, so a failed write still retries. Lock and unlock bump `lockEpoch` and `mutationCounter`: a scan or an unseal that started before is thrown away. A scan never hands text to a sealed note.
- `readText` refuses a file starting with the locked magic, whatever its extension: the CP1252 fallback would decode it as garbage and save that back. `.mdlock` files are library-only (`NoteNaming.isPlainNoteFile` is what opens from Finder); one from elsewhere is refused.
- Names are unique across extensions (`stemTaken`): "Ideas.md" and "Ideas.mdlock" never coexist. A `.md` vanishing while a same-named `.mdlock` appears (or back) is one note locked elsewhere: `reconcile` adopts it, keeping `Note.id` and its tab.
- The debug driver's library uses its own UserDefaults suite (`com.mlutfullaev.minote.driver`), for its lock settings and its open tabs: same bundle id as the installed app, so a test password's vault mirror must never reach the real preferences. It shares the real Backups folder, so give driver notes names no real note has.
- Anything can edit `.minote-vault`, so it's never believed when it asks to lock less: while locked, a folder record saying Selected Notes where this device's copy says Whole Library is held at Whole Library (`applyVault`); unlocked, `confirmScope` takes the scope the key signed (`trustedScope`: the newer `scopeRevision` of the folder's and the device's copy, so an old file put back loses), and writes the trusted one back signed. Every record Minote writes is signed; only one rebuilt from a note's header isn't.
- The recovery key exists only on screen: `setPassword`, `changePassword` and `makeRecoveryCode` return it and the sheets show it until the user says it's kept. Once the password is set, nothing after it may throw past the code (Whole Library failing is reported, not thrown). Password rules are enforced in `Library`, not only in the sheets.
- A note that turns up locked takes this device's plain backups of it along (`NoteFileStore.scan` → `removePlainBackups(ofLocked:)`, by name and by backup ID), also when another device locked it; sealed backups stay.

- Build every library URL from `NoteFileStore.folderURL` / `fileURL(named:in:)` (or from a URL the store gave, as `url.deletingLastPathComponent()`): the library matches notes to scanned files by URL equality, and a URL spelled differently is a note removed and another added.
- Two folders may hold notes of the same name: never look a library note up by its file name alone (`note(atPath:)`). Backups are still matched by name, so locking a note can also delete a same-named plain note's backups elsewhere (accepted: errs on the lock's side).
- A file that vanishes while one with the same name and the same size and modification date appears in another folder is a move made elsewhere (Finder, another device): `reconcile` adopts it, keeping `Note.id`, its tab and edits. Two candidates are a removal and two additions.
- The sidebar rows are rebuilt from `notes`, `folders`, `folderSettings` and the view; only Title sort and search read `Note.title`, so typing in the title line rebuilds the list only then. Never sort by something that changes per keystroke.
- `@MainActor` enums holding a `Note` need `nonisolated` `==` and `id` to conform to `Equatable`/`Identifiable` (the conformance would cross into main-actor code).
- Right-clicks don't reach SwiftUI views as their own events: an app-level monitor (`AppDelegate.secondaryClicks` → `Workspace.handleSecondaryClick` → `WindowState.secondaryClick`) asks the views registered in `secondaryClickHandlers` for items at the point (the sidebar finds the row from its row frames) and shows `ChromeMenu`. Never `.contextMenu`: it's the system's menu.
- The debug app is sandboxed: its driver folder is `~/Library/Containers/com.mlutfullaev.minote/Data/tmp/minote-driver`, not `$TMPDIR`. Driver commands that need a window use `targetWindow` (`frontWindow` is nil while the app isn't active). Driven keys reach SwiftUI focus only while the window is key; driven right-clicks go through the event queue (`postEvent`) so the monitor sees them. Don't rebuild `build/Minote.app` while the user runs it from there: put a debug copy elsewhere.

## iCloud

Container `iCloud.com.mlutfullaev.minote`, shown as "Minote" in iCloud Drive. Only signed builds carry the iCloud entitlements (`Support/Minote-AppStore.entitlements`, `Minote-iOS.entitlements`); local ad-hoc builds use `Minote.entitlements`, where iCloud is simply unavailable. Untested until a signed build exists: verify sync, placeholders and conflicts on two devices, including the hidden `.minote-vault` and each folder's `.minote-folder` (a folder made, renamed, moved or reordered on one device must reach the other) (a lock, a password change and Whole library mode made on one device must reach the other).

## Shipping (needs Xcode + an Apple Developer account)

0. Version and build number live only in `Support/Minote.xcconfig`; bump `CURRENT_PROJECT_VERSION` for every upload.
1. `xcodegen generate`, open `Minote.xcodeproj`, set the Team on both targets, enable the iCloud container in the developer portal.
2. Archive `Minote-macOS` and `Minote-iOS`, upload from the Organizer. Same bundle id on both → universal purchase.
3. App Store Connect: privacy policy URL, "Data Not Collected", screenshots. Export compliance is pre-answered (`ITSAppUsesNonExemptEncryption = NO`); locked notes use only Apple's CryptoKit/CommonCrypto to protect the user's own data, which should keep that answer, but confirm it in App Store Connect before the first upload with locked notes.

# Minote

A quiet place to write: plain Markdown files, a library sidebar, everything else in the menus. Any Markdown file on the Mac (Finder, File ▸ Open… ⌘O, Open Recent, the Dock) opens as a tab of the front window (or a window of its own when none is open) and is edited in place. Tabs on the Mac are Minote's own, IDE-style: a solid bar at the very top of the window (the window buttons sit in it), tabs as wide as fit up to a maximum, scrolling past a minimum; each tab is a rounded plate shaped and shaded like a sidebar row (`SidebarMetrics.rowCornerRadius`). With a single tab the bar shows no tab: it takes the page's paper, keeping its height and buttons, so a second tab doesn't move the page. A note opened takes the place of a library tab nobody typed in (its title is italic; a double-click or "Keep Open" keeps it), otherwise it gets a new tab; files from Finder always get their own tab. ⌘T new tab, ⌘W close it (middle-click too), ⇧⌘W close the window, ⌘1…⌘9, ⌘⇧] / ⌘⇧[, ⌃Tab; tabs drag along the bar, out into a window of their own and into another window's bar; library tabs come back at the next launch. The editor renders Markdown: no markup symbols show. Block markup is hidden or drawn as what it means (bullets •◦▪, clickable task boxes, quote bars, rules, code boxes, table lines); only the *inline* formatting under the caret (`**`, `[]()`) reveals its symbols, so it can be edited. View ▸ Preview (⌘R) is read-only: nothing reveals, a click follows links. In Preview (Mac) a rail of dashes on the page's right edge, one per heading, morphs on hover into a card of heading titles; a click glides the page to that heading and puts the hidden caret there, so leaving Preview continues at it. While editing, ⌘-click follows a link (iOS: tap it when not typing) and hovering shows its address. View ▸ Show Markdown Syntax switches to iA-style dimmed markup. The "Aa" button at the end of the tab bar (Mac) opens a panel with text size, theme (System / Light / Sepia / Dark) and font: the same preferences as the View menu, for writing and Preview alike. Philosophy and interaction model follow iA Writer; name, icon and typeface are our own (iA's fonts may not be bundled — we use IBM Plex Mono, OFL).

## Commands

```bash
scripts/test.sh                      # unit tests (Swift Testing); CI (.github/workflows/ci.yml) runs them and builds both apps on every PR
scripts/build-app.sh --run           # Mac app → build/Minote.app (sandboxed, ad-hoc signed), relaunch
scripts/build-app.sh --universal     # arm64 + x86_64
scripts/build-ios-preview.sh --run   # iOS app compiled for Mac Catalyst → build/Minote iOS Preview.app
xcodegen generate && xcodebuild test -project Minote.xcodeproj -scheme Minote-iOS -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO   # iOS UI tests (real taps)
swift scripts/make-icon.swift        # regenerate AppIcon.icns + Assets.xcassets
xcodegen generate                    # Minote.xcodeproj for App Store archives (needs Xcode to build)
```

## Layout

- `Sources/MinoteKit` — Foundation only, shared by every platform, fully unit-tested.
  - `Library` (`@MainActor @Observable`): notes, selection, drafts, debounced autosave, auto-naming, trash/undo, reconciling outside changes. All disk work for a note is serialized through `enqueue`. Over a single-file store (`isSingleFile`) it holds just that note: no drafts, no saved selection, and a file deleted elsewhere keeps its window (edits are written back to the same path). It serves several editors at once (one per Mac tab): `show(_:in:)`, `activate(_:)`, `detach(_:)`; `selectedID` is the front editor's note, and setting it shows the note in the front editor (iOS has one editor, where nothing changed). Opening on the user's behalf goes through `open(_:)` → `openHandler`; a removed note's editor asks `shownNoteRemovedHandler`.
  - `Tabs`: `OpenPlacement` (where an opened note goes: focus its tab, replace the front one, new tab, new window), `SavedTabs` (library tabs per window, by file name, with the untouched ones, under `OpenTabs`) and `TabStripLayout` (tab widths, scrolling, where a dragged tab lands).
  - `NoteFileStore` (actor): scan, safe write (`replaceItemAt` + xattr copy), create, rename, trash. `init(file:)` is single-file mode for a file opened from elsewhere: only that file, always coordinated, no naming tag, written in place when the sandbox refuses a replace (the grant covers the file, not its folder); create/rename/duplicate/trash throw. In iCloud (`isUbiquitous`): coordinated I/O, downloads `.icloud` placeholders, saves conflict versions as "(conflict)" notes. Emptying a non-empty note first copies it to `LibraryLocation.backupDirectory()` (Application Support/Minote/Backups, device-local, newest 50).
  - `LibraryStorageSwitcher`: opens the library locally or in iCloud Drive and moves notes between them (`LibraryLocation.moveNotes`: `setUbiquitous`, downloads placeholders first, keeps going past failures and reports what stayed). Notes written locally while iCloud was unavailable join iCloud at the next launch.
  - `Markdown/`: `MarkdownLexer` (per-line CommonMark/GFM styling spans, list markers, quote depth, links), `FenceIndex` (incremental code-fence tracking), `MarkdownEditing` (Format actions as pure `TextEdit`s; `hiddenMarkup`/`adjustedCaret`/`deleteMarkup` for the rendered view), `MarkdownLinks` (resolves references, footnotes, `#heading` anchors, other notes), `MarkdownOutline` (the headings the page renders, outside code blocks; `section(at:)`), `TextStatistics`, `Lines` (`NSString.forEachLine`, `characters(in:)`, `NSRange.clamped(to:)`). Anything that reads a line's markers asks `MarkdownLexer` (e.g. `LinePrefix` for Return/Tab/list toggles), so what's drawn and what's edited never disagree.
  - `PathWatcher`: vnode watch of a file or folder that follows replace-on-save (an opened file on the Mac, the library folder on iOS).
- `Sources/MinoteEditor` — AppKit/UIKit shared look: `EditorTheme` (caret, parts of speech, metrics), `EditorPalette` (the page's colors, one instance per `EditorPaper`: standard or sepia), `EditorStyleSheet` (fonts + palette + geometry), `MarkdownStyler` (rendered/source views; hidden markup = 0.01 pt clear font; drawn markup = clear glyphs + `.minoteMark`/`.minoteBlock` attributes), `MarkdownLayoutFragment` (TextKit 2 fragment that draws those marks; installed by `EditorTextEngine.attach(to:)`), `EditorTextEngine` (text-storage delegate: incremental restyle, caret reveal, Preview, Focus mode, caret snapping out of hidden markup, fence-aware Return/Tab/Backspace edits, link/task-box hit testing, title-line and title-prefix queries, `outline()`), `FormatAction`, `SharedViews` (SwiftUI shared by both apps: `ViewState`, `EditorPreferences` — the View menu's `@AppStorage` settings, `FormatMenuItems`, `libraryErrorAlert`). The outline beside the page, shared for iOS later: `OutlineLayout` (rail and card geometry, also used for hit testing), `OutlineMotion` (one `progress`, 0 rail → 1 card, places every element; pure and tested), `OutlineScrolling` (reading line, landing place), `OutlineRailView` (SwiftUI, only draws). Branch on `#if os(macOS)`, never `canImport(AppKit)` (true on Catalyst).
- `Sources/Minote` — macOS app (SwiftUI shell + TextKit 2 `NSTextView`). `Window/Workspace` (owned by `AppDelegate`): every window and tab, the shared library (loaded on first need), where opened notes and files go, moving tabs between windows, recents, saving/termination, tabs kept across launches. `Window/PageWindow`: one AppKit window (not restorable, no system tabs) holding `WindowState` (its tabs, the one in front, the sidebar) and `PageView` = `SidebarColumn` + (`TabBar` over `EditorPage`). `Window/PageTab`: one tab, with its own `EditorCoordinator`, showing a library note or an `OpenedFile` (`Files/`: a single-file `Library` watched by a `PathWatcher`); switching tabs swaps the page's scroll view. `Window/TabBar` (tabs, dragging, "+", the sidebar toggle, `ChromeButtonStyle`), `Window/TitlebarLayout` (the window buttons centered in the bar, `WindowButtonsKeeper`, `WindowDragArea` for the bar's empty parts). `Sidebar/SidebarColumn`: header (window buttons, toggle, New Note), search field, notes (`SidebarView`), resizable edge. `EditorPage` is the page of the tab in front; "Aa" is `Editor/TextSettingsPanel`. `PageTheme` (View ▸ Appearance) picks the app appearance and the paper; Sepia is a light appearance on sepia paper. `Editor/Outline/`: `OutlineController` (owned by `EditorCoordinator`: headings, current section, hover → card, going to a heading), `OutlineOverlayView` (AppKit container in `EditorScrollView` that owns every event, with a passive SwiftUI host inside), `ScrollGlide` (display-link glide to a heading). `Debug/DebugDriver.swift` (DEBUG only): with `MINOTE_DRIVER=1` the app takes commands (click/key/type/hover/snapshot/outline/tabs/open/openfile/mouse/droptab/chrome…) from `$TMPDIR/minote-driver/in`, against its own `DriverNotes` library — interaction tests without the screen.
- `Apps/iOS` — iPhone/iPad app (SwiftUI + TextKit 2 `UITextView`). Not a SwiftPM target; built by Xcode or `build-ios-preview.sh`. Module name `MinoteMobile` (`Minote` is the Mac target). `Tests/MinoteiOSUITests`: XCUITests (DEBUG seed via `MINOTE_UITEST_NOTE`).
- `Support/` — `Minote.xcconfig` (identity + version, single source of truth), Info.plists, entitlements, privacy manifest, container migration.

## Rules that bit us

- An opened file never joins the library list and is never renamed, moved or trashed. A file that is one of the library's notes opens as a library tab instead: two editors on one file overwrite each other. Likewise a note is never shown in two tabs (`Library.show` refuses; opening it again brings its tab forward).
- Opening files must stay light: every window is AppKit's own and made on demand. The SwiftUI scene is an empty `Settings` that only hosts the menus. The library is loaded (scan, FSEvents, iCloud lookup) only when a window shows it: at a launch that opened no files (`applicationDidFinishLaunching`), on reopen (Dock, Launchpad, Spotlight), from a library command, or when a Finder window's sidebar is shown. A launch from Finder costs one window, sidebar hidden.
- A note is wrapped up (blank draft dropped, renamed to its title, emptied file trashed) when no editor shows it any more, not when the selection moves: a background tab is still open.
- The editor belongs to its tab (`PageTab` makes it; the workspace attaches it to the library at once), not to SwiftUI: routing asks the library which editor shows a note before SwiftUI has laid anything out. A tab moved to another window takes its editor along.
- `PageTab.isEdited` (the untouched-tab rule) is set once per note, not per keystroke: typing never goes through SwiftUI.
- Save state as it changes, never only at quit: `NSSupportsSuddenTermination` is on, so ⌘Q with nothing unsaved ends the app without calling `applicationShouldTerminate`. Tabs are saved on every change (`Workspace.tabsDidChange`, coalesced).
- The tab bar is ours (`allowsAutomaticWindowTabbing` is off). Its Window menu items are in `AppCommands`; the tab shortcuts and middle-click are handled in `AppDelegate` (`handleTabKey`, `handleMiddleClick`) so they work regardless of focus.
- The tab bar lies where the titlebar would be. AppKit moves the window from a press on anything there that doesn't refuse it, and SwiftUI's views don't: `PageNSWindow.sendEvent` turns moving off for presses on the bar's controls; only `WindowDragArea` moves the window. AppKit lays its titlebar out again whenever it likes (a new title puts the zoom button back, silently): `WindowButtonsKeeper` re-centers the buttons after frame changes and every window update, and `PageWindow.updateTitle` lays out at once.
- `NSEvent.clickCount` raises on anything but a mouse down/up: check the event type first. An exception swallowed inside a SwiftUI gesture leaves Swift's executor state broken and the app crashes later, somewhere unrelated.
- The sidebar draws its own rows (`SidebarView`: ScrollView + `NoteRow`, `EditorTheme.sidebar*` colors). Don't go back to a system `List(.sidebar)`: its translucency and accent-colored selection can't be restyled to match the page. Nor to `NavigationSplitView` or a window toolbar: the column, its search field and the bar are ours, so nothing floats over the page or sits under the titlebar.
- Menus act on the front tab: in `AppCommands` use `front` (`Workspace.frontTab`) for editor commands, `frontWindow` for the window's state, and `frontLibraryNote` for library-only commands (disabled for a file from Finder).
- Page colors come from the style sheet's palette (`styleSheet.palette`), never a global: a theme change is an `EditorConfiguration.paper` change, which rebuilds the style sheet and restyles like a font change. SwiftUI and window backgrounds read `PageTheme.palette`; each paper has its own color instances, so SwiftUI notices the change. Printing always uses standard ink.
- Build fonts from descriptors, not names: system faces (New York) have private names that don't resolve (`NSFont(name: ".NewYork-Regular")` is nil), and the full-size fallback left gaps where markup is hidden.
- Typing never goes through SwiftUI state. The library drives the editor via the `NoteEditor` protocol.
- Smart Return, Tab and Backspace go through `EditorTextEngine` (`newlineEdit`, `listShiftEdit`, `markupDeletion`), never `MarkdownEditing` directly: only the engine knows where code blocks are.
- Idle must cost nothing: no repeating Core Animation (the caret blinks with a timer; a repeating animation keeps the render server drawing every frame). A keystroke styles its line once: `EditorTextEngine` shifts the revealed lines with the edit so the selection change that follows doesn't restyle them.
- The lexer runs on every keystroke for the edited line: keep it linear (a long pasted line once took 21 s; see `longLinesFullOfDelimitersStayFast`).
- Files Minote didn't create are never renamed (auto-naming is gated on the `com.mlutfullaev.minote.autoname` xattr).
- TextKit 2: `baselineOffset` has its standard meaning inside a fixed line height (negative = lower); a positive one shrinks the line. `NSTextLineFragment.glyphOrigin` is the baseline *before* the offset: drawn baseline = `glyphOrigin.y - baselineOffset`. `drawInsertionPoint` is ignored, hence `CaretView`.
- Overlays above the page (`EditorScrollView.outlineOverlay`) are a plain NSView that decides hit testing, the cursor and scrolling with the same layout that draws, around a SwiftUI host whose `hitTest` is nil (`sizingOptions`, `safeAreaRegions`, `sceneBridgingOptions` all empty, or every animation frame relayouts the window). The text view's `.inVisibleRect` tracking area still fires under an overlay: `WriterTextView` asks `isPointerOverOutline` before touching hover or the cursor. Never override `scrollWheel` on the scroll view or the text view (it opts them out of responsive scrolling).
- Animate a jump to a line by its distance from the top of the page, measured again every frame (`ScrollGlide`), never with `clip.animator()`: TextKit 2 replaces estimated heights while laying out, so a fixed scroll target misses and correcting it at the end jumps.
- Never give the Mac editor's NSScrollView a bottom `contentInsets`: AppKit treats that band as outside the page, so clicks there were swallowed or started a selection to the end of the note. Scroll-past-end is `WriterTextView.bottomPadding` (taller view + `textContainerOrigin` override).
- The engine restyles whole lines inside `willProcessEditing`, which widens the edited range TextKit 2 sees; it moves a caret inside that range to its end. `WriterTextView` records the expected caret in `shouldChangeText` and restores it in `didChangeText` (typing mid-line used to jump to the next line).
- The caret never rests inside hidden block markup (`EditorTextEngine.adjustedSelection`). Only keyboard moves may step back out of a line (pass `previous` for those, nil for clicks: a click sets the selection twice). NSTextLayoutManager rendering attributes don't reliably recolor NSTextView text, so Focus mode restyles storage. After replacing the whole text, call `layoutViewport()` or only the old viewport renders.
- The SwiftPM scripts work with Command Line Tools alone: SwiftUI's `@State` is a macro whose plugin ships only with Xcode → use the `ViewState` typealias (MinoteEditor). Swift Testing's macro plugin needs `-plugin-path` (see `scripts/test.sh`). Xcode 27 is now installed too (iOS simulators, UI tests, archives).
- macOS bash is 3.2: guard empty arrays under `set -u`.

## iCloud

Container `iCloud.com.mlutfullaev.minote`, shown as "Minote" in iCloud Drive. Only signed builds carry the iCloud entitlements (`Support/Minote-AppStore.entitlements`, `Minote-iOS.entitlements`); local ad-hoc builds use `Minote.entitlements`, where iCloud is simply unavailable. Untested until a signed build exists: verify sync, placeholders and conflicts on two devices.

## Shipping (needs Xcode + an Apple Developer account)

0. Version and build number live only in `Support/Minote.xcconfig`; bump `CURRENT_PROJECT_VERSION` for every upload.
1. `xcodegen generate`, open `Minote.xcodeproj`, set the Team on both targets, enable the iCloud container in the developer portal.
2. Archive `Minote-macOS` and `Minote-iOS`, upload from the Organizer. Same bundle id on both → universal purchase.
3. App Store Connect: privacy policy URL, "Data Not Collected", screenshots. Export compliance is pre-answered (`ITSAppUsesNonExemptEncryption = NO`).
